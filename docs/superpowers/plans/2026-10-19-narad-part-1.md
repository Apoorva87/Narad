# Narad Part 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver a local, persistent lesson reader for user feedback before adding generation, speech, and tutoring.

**Architecture:** Shared TypeScript lesson contract, SQLite-backed Express API, React reader. Store source snapshots and explicit content blocks; serve saved diagrams locally. No agent or TTS process in this checkpoint.

**Tech Stack:** Node >=24, React, Vite, TypeScript, Express, node:sqlite, Zod, react-markdown, remark-math, rehype-katex, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-19-narad-design.md`

## Global Constraints
- Local single-user app; no hosting, accounts, collaboration, or cloud speech required for version one.
- Stop after each checkpoint, demonstrate working behavior and limits, and request feedback.
- Do not build stages 2–4 in stage 1.
- Familiarity never reduces detailed factual coverage.
- No fake speech, generation, tutor answers, familiarity rewrites, or session counts.

## Review Focus
- Imported lessons with duplicate block IDs or dangling references must be rejected before storage (Task 1 tests).
- Malicious HTML/URLs and broken images must not execute or silently disappear (Task 1 tests, Task 3 browser checks).
- Refreshing or changing modes must not restore a block from the wrong lesson/mode (Task 2 persistence tests, Task 3 browser checks).
- Sparse imports with only one mode must show only available content, without crashing or claiming missing modes exist (Task 3 browser checks).
- Mobile equations, long titles and open dialogs must remain usable without page-wide overflow (Task 3 browser checks).
